# Codex exec: empirical test of headless approvals, managed policy and skills (AW-18)

Run 2026-11-12 on this machine with `codex-cli 0.162.1`, using a throwaway git repo (deleted afterwards). Facts observed, no recommendations. Each run: `codex exec --json --ephemeral` in the repo, stdin closed. Raw event streams were not kept. Files under `~/.codex` other than the key names listed below were not read; `config.toml` was grepped only for `approval_policy`, `sandbox_mode`, `approvals_reviewer`, `default_permissions` (none present).

## Findings

1. **stdin must be closed.** With stdin an open pipe, `codex exec "<prompt>"` prints `Reading additional input from stdin...` and blocks until EOF (first run hung until killed at 150 s with no events). Redirecting `< /dev/null` fixes it.
2. **Managed policy applies to `codex exec`, and is cloud-delivered here.** No `/etc/codex`, no `~/.codex/requirements.toml`, no `managed_config.toml` exist on this machine. `~/.codex/cloud-config-bundle-cache.json` exists: a signed payload with `bundle.config_toml.enterprise_managed` and `bundle.requirements_toml.enterprise_managed`, cached with `cached_at`/`expires_at`. Every run emits three `item.completed` events of `type: "error"` (non-fatal notices) quoting "enterprise-managed requirements Baseline": `windows.sandbox` must be `Elevated`; `approval_policy` value `Never` "is not in the allowed set [OnRequest, UnlessTrusted]; falling back to required value OnRequest". Process exit code stays 0.
3. **`exec` configures `approval_policy = Never` itself, and `-c approval_policy=...` does not change that.** The notice reports `Never` as the configured value even with no `-c` and with `-c approval_policy="on-request"`; managed requirements then force `OnRequest`. `-c approval_policy="untrusted"` fails with "approval_policy = "untrusted" is no longer supported; remove this setting"; `-c approval_policy="unless-trusted"` fails config load with "unknown variant ... expected one of untrusted, on-failure, on-request, granular, never".
4. **A sandbox denial is a plain command failure, with no approval event.** `--sandbox workspace-write`, writing a file outside the workspace (and outside `/tmp`, which workspace-write allows): the shell command fails with `operation not permitted`; the model reports it; no approval-related event; exit 0. (A write under `/private/tmp` succeeded because workspace-write permits temp dirs.)
5. **An escalation request cannot be approved in plain `exec`.** Asking the model to run a command with `require_escalated` permissions: the `command_execution` item completes with `status: "failed"` (exit_code `-1` for the network case), the model reports "approval request failed", and stderr logs `codex_app_server::bespoke_event_handling: request failed with client error ... "command execution approval is not supported in exec mode"`. Process exit 0; the file was not written. A `curl https://example.com` under workspace-write behaved the same way (approval request failed, command not run).
6. **`--approve-for-me` is a working headless approval path.** `codex exec --approve-for-me` with the same escalation prompt: the command ran outside the sandbox and succeeded (`status: "completed"`, exit 0) and the file was written; the model reported approval granted. No managed-policy `approval_policy` notice appeared on that run. This routes approvals to an automatic reviewer (a model), not to a human.
7. **Skills load under `exec`.** A repo-level `.agents/skills/probe-skill/SKILL.md` appeared in the model's list of available skills under `codex exec --sandbox read-only`, alongside built-in skills and user-level skills from `~/.agents/skills`. Implicit invocation of the probe skill was not tested.

## Not tested / uncertain

- `danger-full-access` and `granular` approval policies (not run: the former would bypass the sandbox).
- The allowed sandbox modes in the managed requirements (not read from the bundle; only observed behavior).
- Whether the automatic reviewer in `--approve-for-me` is itself constrained by `allowed_approvals_reviewers` in the requirements, and what it refuses.
- Behavior on other Codex versions; flags and config values changed between releases (item 3).
