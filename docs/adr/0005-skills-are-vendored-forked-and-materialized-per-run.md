# Skills are vendored, forked where Warden-shaped, and materialized per run

The mattpocock/skills the factory uses are vendored into the factory repo as a snapshot pinned to an upstream commit, and the Works never fetches skills at runtime: skill text is instructions executed under the developer's managed permissions, so upgrades are a deliberate, reviewed change. Warden-shaped skills (`implement-spec`, `code-review`, `triage`) are forked and owned by the factory with provenance recorded, edited to dispatch through `dispatch_wright` and to fill the gaps upstream leaves (failure handling, rework limits, per-piece inspection); we rejected an adapter-prompt overlay because it would break whenever upstream changes how it dispatches.

Before each run the Works makes a per-run copy of the Guild's skill set so every run sees a pinned, isolated set and skills that call other skills still resolve; it is written to `.agents/skills` in the worktree for both runners (with a `.claude/skills` symlink for Claude) and hidden from git for the run through git configuration supplied by the Works, as set by ADR 0018. Skills that need a human and a Site run under a Wright, with the request for a human flowing up to the Archwright (ADR 0015 refines this: intent-only interrogation skills run in the Archwright's own session). A Project must carry the `setup-matt-pocock-skills` configuration before it accepts Jobs.
