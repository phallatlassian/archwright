# Wrights work in Works-managed worktrees; the Warden opens the PR after the Archwright's go-ahead

Every writing Wright gets its own git worktree on its own branch, created by the Works from the brief's base ref in a Works-managed directory outside the Project checkout; read-only Wrights get a detached worktree; no agent ever runs in the developer's own checkout. Each Job has an integration branch, into which a merge Wright merges finished Wright branches. The factory commits to local branches and never touches the Project's default branch. Concurrent Jobs on one Project are allowed with independent integration branches; the Works warns in the Needs-you inbox when their declared scopes overlap but does not block, and conflicts surface at merge time.

The Engineering Warden itself pushes and opens the PR (the `pr` skill, under the runner's normal permission rules) once all checks have passed and the Archwright gives the go-ahead; the developer is not prompted, so the managed permission model, not a factory checkpoint, is what can stop a push. The Works caps parallelism at 4 concurrent runs overall, 3 per Project and 3 Wrights per Warden task by default (configurable), queues the excess, and pauses a runner with backoff on rate-limit errors. Wright worktrees are removed once merged; integration worktrees and anything from failed or interrupted runs are kept until the developer accepts or discards the Job.
