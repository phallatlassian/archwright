# The factory fails closed on permission prompts and can never widen permissions

Agents run under exactly the permissions of the developer running `claude` or `codex` from a terminal, under the company managed policy, so the factory has no way to approve anything on a runner's behalf. When a headless Wright hits an action that would prompt, the action is denied (as both runners already do); the adapter records a normalized `permission_denied` event with the tool and exact command, the Wright returns `blocked` citing it, and a "permission wanted" item appears in the Needs-you inbox. The developer fixes it in their own permission rules and the Warden re-dispatches, or skips it. There is no live approval relay in v1: Claude would need an approval hook or MCP prompt tool that managed policy may forbid, and plain `codex exec` cannot approve an escalation at all. Codex's `--approve-for-me` is not used, because it substitutes an automatic model reviewer for the human.

A never-list is hard-coded in the adapters and not configurable: never pass `bypassPermissions`, `--dangerously-skip-permissions`, `--yolo`, `danger-full-access`, a permission mode or approval policy more permissive than the runner's default, or `--approve-for-me`; never write any settings file (managed, user or project) or add an allow rule; never disable the sandbox or set `dangerouslyDisableSandbox`; never pass `--settings` or `--mcp-config` that overrides managed keys. Adapters refuse to spawn when asked to. Each run records its permission posture (runner, version, mode, sandbox, flags, managed-policy notices) as an event, and a runner that refuses to start because managed policy is unparseable fails visibly with nothing retried around it.
