# Every agent works in a worktree of one trusted main checkout, and the Warden merges there

Status: proposed until the live check (#191) confirms that both CLIs inherit folder trust into worktrees of a normal clone. Amends ADR 0019, ADR 0028, ADR 0026 (its trust paragraph, in `docs/spec/tmux-runtime.md`) and ADR 0009.

A shakedown asked the developer to trust the folder at nearly every agent launch. Neither CLI treats a path as trusted just because its parent is: Claude keys trust on the git repository root and, for a worktree, on the main checkout's root; Codex matches exact keys (the directory, its project root, its repo root) and likewise resolves a worktree to its main checkout root, but not for a worktree of a **bare** clone, and neither covers a freshly `git init`'d folder (Claude Code permissions docs, "Project allow rules and workspace trust"; `codex-rs/git-utils/src/trust.rs` and `codex-rs/config/src/loader/mod.rs` at openai/codex af71942). The Works kept a bare clone per Site (ADR 0019) and gave each Warden a per-run directory it `git init`'d, so every Job worktree and every Warden was a new untrusted path. The Works never writes trust configuration (ADR 0027), so it cannot trust a new path itself.

**Decision.** A Site's clone is a **normal clone with a main checkout** that no agent edits or runs in (the trust probe excepted). The developer trusts that one folder once per runner, and every worktree created from it inherits trust, so every agent of the Site starts without a dialog: Wrights, review checkouts and Wardens. The Archwright's factory home is trusted once separately.

- **Warden worktrees.** A Warden no longer works in a `git init`'d directory. Its cwd is a worktree of the main checkout whose kind a `worktree:` property declares in GUILD.md (default `empty`), overridable per Jig or Plan step; a definition can only narrow, never widen (ADR 0009). Kinds: `integration` (the Job's single full worktree, shared by every Guild that asks for it in a Job, one writer at a time), `branch` (its own branch), `detached` (read-only full checkout) and `empty` (a `--no-checkout` worktree, which inherits trust but holds almost no files). Masonry declares `integration`, and its Warden pushes and opens the PR from it; Review keeps its fresh detached checkout so a reviewer never shares the builder's tree (ADR 0012). The property is called `worktree:`, not `workspace:`, because the glossary reserves that word for what a Site is not.
- **The Warden merges.** The Masonry Warden merges accepted piece branches into the integration branch itself, in its own worktree. On a conflict it sends the piece back to the same Wright (a rework round, ADR 0029) to resolve, so there is no merge Wright and the Works no longer runs `git merge` in the Warden's tree. This amends ADR 0028's "A Warden never does a mechanical merge". What ADR 0028 kept stays: the Works runs the Site's gates on a Snapshot of the worktree at handback, outside any agent, and that run stays authoritative.
- **Migration.** A Site with a bare clone and no active Jobs is migrated by the Works at start (re-clone, keep Job history, run the trust probe in the new main checkout, leave old worktrees until their Jobs close); otherwise a doctor warning and a Needs-you item say it is waiting. It is gated on the live check.
- **Stalled launches.** An agent that sends no SessionStart within a few seconds raises a Needs-you item with the attach command, and the Works moves tmux focus to its pane only when the attached client has been idle for a few seconds, so a stray keystroke cannot answer another agent's prompt (ADR 0027).

**Considered: a fixed pool of worktree paths per Site**, trusted once each and reused by Jobs. It needs no change to the clone, but needs a pool size per Site, a reset policy, a wait-when-full rule, and a trust step per slot and runner. Kept in reserve if the live check shows a CLI does not inherit trust into worktrees of a normal clone.

**Consequences.** A normal clone re-introduces a working tree that ADR 0019's bare clone deliberately did not have, so the Works must never run an agent in the main checkout, and nothing checks it out except the Works. A `--no-checkout` worktree's `git status` must be made quiet (an empty cone-mode sparse checkout if needed). The Warden's wider role, including whether a Warden edits the repo, remains open for a later decision and is not blocked by this one.

Implementation: #192 (normal clone, probe and migration), #193 (`worktree:` property and Warden worktrees), #194 (the Warden merges), #195 (stalled launches), #191 (live check).
