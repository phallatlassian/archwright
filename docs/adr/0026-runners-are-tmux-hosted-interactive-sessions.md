# Runners are tmux-hosted interactive Sessions of the stock vendor CLIs

The Works runs every agent (the Archwright, each Warden and each Wright) as an interactive Session of the developer's own `claude` or `codex`, in a pane of a tmux server the Works owns. This supersedes ADR 0003, which spawned the same CLIs headlessly. The headless shape forced a growing pile of workarounds under the developer's managed policy (denied actions ending a run `blocked`, computed Codex writable roots, Works-run gates and commits, brokered Forge actions), and left the developer unable to watch an agent, approve a prompt where it appears, or talk to a Wright. A Session keeps the stock binary, login and managed policy of a terminal run, and adds no vendor SDK to the Works.

The runner contract is launch(brief, working directory, limits), which starts a Session in a pane; state derived from the vendors' hooks; Nudge; cancel; and resume by id. Capability flags stay, and a Guild's definition still declares its default runner and model and the permitted set; the Works refuses to bind a Guild to a runner lacking a capability it requires (ADR 0003's rule, kept). The stream-json and `codex exec --json` event normalisation is gone: the Works learns what a Session is doing from hooks (observe-only, ADR 0027) and reads its transcript from the path the SessionStart hook reports. The Posture record keeps what still applies: runner, version, mode, flags and managed-policy notices.

The Works owns the topology: one tmux server on a dedicated socket, so the developer's own tmux is never touched, holding one `factory` session with an `archwright` window and one window per Job; a Job's window holds a pane per Warden and per Wright. Pane ids are recorded per run in SQLite and are canonical (ADR 0002). Panes get an allowlisted snapshot of the developer's shell environment, a Works-supplied tmux config sources the developer's own first, and `remain-on-exit` keeps a dead pane's final screen readable. tmux is a hard dependency with no headless fallback; `archwright doctor` checks it. A developer may type into any pane; the Works records that a human interacted and never blocks it (ADR 0029).

Handback, briefs and tool calls are unchanged: `archwright tool` and the spool (ADRs 0014, 0018, 0006) carry them. The brief is the first prompt, passed as the positional argument. Mechanics (launch lines, the state machine, Nudge rules, hook payload fields, tmux options, the trust probe) live in `docs/spec/tmux-runtime.md`, not here.

Supersedes ADR 0003. Amends ADR 0001 (the Archwright is spawned and owned by the Works), ADR 0002 and ADR 0017 (see their footers).
