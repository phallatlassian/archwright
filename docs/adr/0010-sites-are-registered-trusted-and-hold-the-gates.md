# Sites are registered and trusted, and the Works holds their gate commands

A repository enters the factory only by being registered as a Site, an act the developer confirms through the Archwright, because headless runs load a repository's project-level hooks and MCP servers with no trust dialog; registering is how that trust is granted, and the Works refuses unregistered paths (ADR 0019 amends this: Sites are registered by remote URL, and a directory is matched by its `origin`). Registration stores in the Works registry the name, remote URL and the Works' clone of it (ADR 0019 replaces the local path), base branch, the result of the `setup-matt-pocock-skills` configuration check, the concurrency cap and the gate commands (type-check, lint, test), with defaults detected from the repository and confirmed by the developer. The gate commands live in the registry rather than the repository so that a Wright's branch cannot weaken the checks the Works re-runs on handback; changing them is a developer-approved command.

The one Archwright runs in a neutral factory home directory with only user and managed settings plus the Works tools, and never reads or edits a Site itself; the `archwright` CLI passes the directory you launched from as a hint of the current Site (matched by that directory's `origin` URL, ADR 0019). Wrights run in worktrees of the Site, so its own settings, AGENTS.md and skills apply as when the developer works there, with user and managed settings on top and always winning; the factory injects nothing that widens permissions. A Job belongs to exactly one Site in v1, and cross-Site work is separate Jobs the Archwright sequences.
