# The Archwright is a stock interactive agent session, not a custom chat program

The Archwright is an ordinary interactive `claude` or `codex` session launched by the `archwright` CLI, with factory tools called through the `archwright tool` CLI (ADR 0014; an MCP shim only where policy allows) and a hook-based inbox for dashboard commands. We chose this over a Works-owned conversation (headless/SDK plus our own chat front-end) because it keeps the developer's permissions exactly those of running the agent from a terminal, under the company managed permission model, and costs the least to build. The price: the Archwright acts on an inbox item only when it next reads its inbox, so anything that must act instantly (such as cancelling a running Job) has to be done by the Works itself and reported to the Archwright. Turn boundaries are not the only place it reads: on Claude Code, the Works posts a short fixed nudge ("your inbox has unread items: read it") to the session's own inbox socket whenever it files an item, which starts a turn in an idle session and reaches a running one between tool calls, and a `PostToolUse` hook delivers the unread items mid-turn. The nudge never carries item content, so the session stays stock and the inbox stays the only source of what the developer or the Works said. A session without the socket (codex, or an older Claude Code) is woken by nothing, so it waits in `read_inbox` with `wait_seconds` rather than end its turn.

There is one Archwright for the whole factory, not one per Job or repository. Which runner backs it is configured per install.

Where the Archwright needs structured input from the developer (an escalated ask, ADR 0015), it renders a Lavish page from its own session rather than building a chat front-end; the page is generated by the Archwright, and the Works is told the answer through the same tool CLI.

Amended by ADR 0026: the Archwright is a Session the Works spawns and owns in tmux, and the Works delivers inbox text to it by Nudge when it is idle (ADR 0029), replacing the hook-based inbox socket.
